Language models can propose formal proofs, while proof assistants check the resulting proof terms. A useful research workflow must also preserve the exact statement being proved, make verification conditions inspectable, and retain artifacts that another user can find and check. Lean2LLM develops these concerns around an existing local Lean-LLM bridge. Its proposal loop fixes the context and proposition, supplies Lean's actual goal and diagnostics to an external proposer, and accepts an exported proof only after Lean checking and a transitive axiom audit. An exact-request cache rechecks every hit. A separate content-addressed proof library adds indexed retrieval, explicit toolchain identities, portable bundles, and local verification records. A browser workbench checks restricted core Lean source in a fresh WebAssembly worker and exchanges records with the Python library. Retrieval proposes an artifact for use; a fresh check establishes its status in the receiving environment. A second verification profile accommodates standalone kernel certificates, drawing on a published Navier-Stokes reproducibility bundle. This paper documents the architecture, artifact schema, trust boundaries, and reproduction procedure. It reports inherited repository evidence separately from tests of the new storage implementation. The contribution is a practical composition of proof generation, checking, storage, and retrieval.
